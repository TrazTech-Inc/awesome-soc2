# Contributing to Awesome SOC 2

Thank you for your interest in contributing to this list! Your help makes this resource better for everyone navigating SOC 2 compliance.

## Guidelines

### What belongs on this list

- Tools, frameworks, guides, and resources directly relevant to SOC 2 compliance
- Resources that are actively maintained and publicly accessible
- Commercial products that are well-established and widely used in the SOC 2 ecosystem
- Open-source tools that help with SOC 2 evidence collection, control implementation, or audit preparation
- Educational content (books, courses, podcasts) that provide genuine value to SOC 2 practitioners

### What does NOT belong

- Resources that are paywalled with no free tier or trial (unless they are industry-standard tools)
- Self-promotional content without genuine educational or practical value
- Outdated resources that have not been updated in more than 3 years
- Duplicate entries that cover the same tool or resource already listed
- Resources unrelated to SOC 2 or its underlying Trust Services Criteria

### Quality standards

Every entry should:

1. **Be genuinely useful** to someone preparing for, undergoing, or maintaining SOC 2 compliance
2. **Have a working link** that resolves to the correct resource
3. **Include a concise description** explaining what the resource is and why it is relevant to SOC 2
4. **Be placed in the correct section** of the list

## How to contribute

### Adding a new resource

1. Fork this repository
2. Create a new branch: `git checkout -b add-resource-name`
3. Add your resource to the appropriate section in `README.md`
4. Follow the existing format: `- [Resource Name](https://url) - Brief description.`
5. Ensure your description ends with a period
6. Submit a pull request using the provided PR template

### Suggesting a new section

If you think a new section would improve the list:

1. Open an issue describing the proposed section and what it would contain
2. Include at least 3 example resources that would go in the new section
3. Explain why the existing sections do not adequately cover these resources

### Fixing issues

- Broken links: Submit a PR with the corrected URL, or open an issue if you cannot find the new URL
- Incorrect descriptions: Submit a PR with the corrected description
- Outdated entries: Submit a PR removing the entry or updating it, with a note explaining why

### Format

```markdown
- [Resource Name](https://example.com) - Description of the resource and its relevance to SOC 2 compliance.
```

- Use title case for resource names
- Descriptions should be one sentence, starting with a capital letter and ending with a period
- Do not use trailing slashes on URLs unless required for the link to work
- Place new entries at the end of their respective section (maintainers will re-sort as needed)

## Pull request process

1. Ensure your PR has a clear title describing the addition or change
2. Fill out the pull request template completely
3. One resource per pull request (unless adding a new section with multiple entries)
4. Allow maintainers a reasonable time to review; we aim to respond within 7 days

## Code of conduct

Be respectful, constructive, and professional. We are all here to build a useful resource for the SOC 2 community.

## Questions?

If you have questions about whether a resource belongs on this list, open an issue and we will discuss it.
